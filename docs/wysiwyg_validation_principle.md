# WYSIWYG Validation Principle

## 1. 핵심 원칙

`Leader_Lab`의 모든 UI/기능/DB/백테스트/시뮬레이션은 다음 원칙을 위해 존재한다.

> What You See Is What You Get.
>
> 화면에서 보이는 분석 순위가 실제 종목별 최고수익률 순위와 얼마나 일치하는지 눈으로 검증할 수 있어야 한다.

즉, 사용자가 최종적으로 보고 싶은 것은 단순한 지표값이나 예쁜 차트가 아니다.

사용자가 보고 싶은 것은 다음 한 줄이다.

```text
분석 순위 Top10 = 실제 최고수익률 Top10과 얼마나 일치하는가?
```

---

## 2. 모든 구현은 역산 구조여야 한다

구현 순서는 기능 중심이 아니라 목표 역산 구조여야 한다.

잘못된 순서:

```text
UI 만들기
→ 데이터 모으기
→ 지표 계산하기
→ 백테스트 붙이기
→ 나중에 수익률 확인
```

올바른 순서:

```text
실제 최고수익률 순위 확인
→ 이 순위를 사전에 맞힐 수 있는 feature 탐색
→ feature를 점수화
→ 분석 순위 생성
→ 실제 최고수익률 순위와 나란히 비교
→ 적중률이 올라가는 방향으로만 기능 추가
```

## 3. 화면이 반드시 보여줘야 할 기본 비교

일자별 화면은 반드시 다음 비교표를 제공해야 한다.

| Actual Rank | Code | Name | MaxRet | Score Rank | LeaderScore | Hit |
|---:|---|---|---:|---:|---:|---|
| 1 | ... | ... | +24.68% | 1 | 92.1 | OK |
| 2 | ... | ... | +22.73% | 4 | 81.5 | OK |
| 3 | ... | ... | +18.79% | 2 | 88.3 | OK |
| 4 | ... | ... | +11.84% | 8 | 73.0 | OK |
| 5 | ... | ... | +11.57% | 15 | 55.2 | MISS |

그리고 반대 방향도 보여야 한다.

| Score Rank | Code | Name | LeaderScore | Actual Rank | MaxRet | Result |
|---:|---|---|---:|---:|---:|---|
| 1 | ... | ... | 92.1 | 1 | +24.68% | HIT |
| 2 | ... | ... | 88.3 | 3 | +18.79% | HIT |
| 3 | ... | ... | 85.0 | 18 | +1.25% | FAIL |

## 4. 최종 확인 지표

화면과 리포트는 다음 수치를 반드시 보여야 한다.

```text
Hit@10 = Score Top10 안에 실제 MaxRet Top10이 몇 개 들어왔는가
Hit@5  = Score Top5 안에 실제 MaxRet Top5가 몇 개 들어왔는가
Label10Rate = Score TopN 중 MaxRet >= 10% 종목 비율
Lift = 랜덤 선택 대비 개선 배수
NDCG = 실제 순위와 분석 순위의 정렬 일치도
```

현재 기준:

```text
10개 중 2개 = 현 수준 / 최악 기준선
```

목표 기준:

```text
10개 중 7개 이상 = 강력 통과
```

## 5. UI 탭별 책임

### Daily Update

데이터가 빠졌는지 확인한다.

목표:

```text
검증 대상 데이터가 빠짐없이 준비되었는가?
```

### 1516 Collector

성과검증 정답 라벨을 저장한다.

목표:

```text
Actual MaxRet 순위를 정확히 저장했는가?
```

### Candle Cache

분석 feature의 원천 데이터를 저장한다.

목표:

```text
Actual Rank를 맞힐 feature 계산에 필요한 일봉/분봉 데이터가 충분한가?
```

### Data Quality

데이터 품질을 검증한다.

목표:

```text
누락/중복/날짜 불일치/종목코드 매핑 실패가 없는가?
```

### Custom Screener / LeaderScore

분석 순위를 생성한다.

목표:

```text
Score Rank가 Actual MaxRet Rank와 가까워지는가?
```

### Backtest / Simulation

선별 순위가 실제 매매 가능 수익으로 이어지는지 확인한다.

목표:

```text
Score Top10을 실제로 샀을 때 기대 수익이 유지되는가?
```

## 6. 데이터/로직/백테스트의 역할

### 데이터

역할:

```text
실제 최고수익률과 사전 feature를 같은 날짜/종목 단위로 연결한다.
```

### 로직

역할:

```text
Actual MaxRet 상위 종목이 공통적으로 가졌던 사전 조건을 점수화한다.
```

### 백테스트

역할:

```text
그 점수화 로직이 미래 구간에서도 동일하게 작동하는지 검증한다.
```

### 시뮬레이션

역할:

```text
점수 상위 종목을 실제 매수/매도 정책에 넣었을 때 수익 구조가 유지되는지 확인한다.
```

## 7. 구현 우선순위 판정 기준

새 기능을 추가하기 전 반드시 묻는다.

```text
이 기능이 Score Rank와 Actual MaxRet Rank의 일치율을 높이는 데 직접 기여하는가?
```

예:

- 1분봉 저장: 필요
- 3/5/15분봉 조립: 필요
- SuperTrend/JMA feature: 필요
- 주도섹터/뉴스/프로그램순매수 feature: 필요
- 단순 장식용 UI: 후순위
- 적중률과 연결되지 않는 차트: 후순위

---

## 8. 최종 산출물

최종 UI/리포트는 반드시 다음을 제공해야 한다.

1. 날짜별 Actual Rank vs Score Rank 비교
2. Score Top10의 실제 Top10 적중 개수
3. Score Top5의 MaxRet >= 10% 비율
4. 실패 종목 분석
5. 적중 종목의 공통 feature 분석
6. Train/Validation/Test 구간별 유지 여부
7. PermanentLeaderScore_vN.yaml

---

## 9. 핵심 문장

`Leader_Lab`은 화면에 보이는 분석 순위가 실제 수익률 순위와 일치하도록 만드는 프로젝트다.

```text
눈으로 검증된 종목별 최고수익률 순위
=
분석 순위
```

이 등식에 가까워지는 방향으로만 데이터, 로직, 백테스트, 시뮬레이션, UI를 파생 구현한다.
